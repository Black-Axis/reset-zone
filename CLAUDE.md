## Overview

**reset-zone** is a modern hybrid SCSS/CSS reset library. There is no JS runtime — the package ships SCSS source and compiled CSS consumed by other projects via npm/yarn/pnpm or CDN. No test suite exists in this repo.

## Commands

- `yarn dev` — full watch pipeline: compiles both regular + layer SCSS, lints, adds banner, minifies both variants, syncs version (runs 7 sub-scripts concurrently via `concurrently`)
- `yarn scss:watch` / `yarn scss:layer:watch` — compile a single variant (`sass --watch`, no source maps)
- `yarn lint` — `stylelint "./src/**/*.scss" --fix`
- `yarn version:sync` — sync `@version` comments in every `src/**/*.scss` + `index.scss`, and add a CHANGELOG.md entry, to match `package.json`'s version (also runs automatically on `postversion`)
- `yarn version:check` — dry-run of the above
- `yarn version:update <version>` — set an explicit version instead of syncing
- `yarn upgrade` / `yarn check-updates` — bump/check deps via `npm-check-updates`
- `yarn cmt` — commitizen conventional commit prompt

There is no build/test/typecheck command beyond `lint` and the `sass` compile — don't hunt for one.

## Architecture

- **`index.scss`** is the public entry point. It defines two mixins: `rz()` (plain reset) and `rz-layer($layer-name: reset-zone)` (same reset wrapped in a CSS `@layer`). Both just include `Core.reset-zone` from `src/modules`.
- **`src/modules/_index.scss`** is the barrel file. Its `reset-zone()` mixin composes 11 module mixins in a fixed, cascade-significant order: `box-sizing → root → body → typography → layout → media → lists → forms → tables → dialog → print → accessibility`. Preserve this order when adding/reordering modules.
- Each module is a self-contained file at **`src/modules/_<name>.rz.scss`** with one mixin, no cross-module imports.
- **`src/reset-zone.regular.scss`** and **`src/reset-zone.layer.scss`** are the actual `sass` CLI compile targets — they just `@include Core.rz` / `Core.rz-layer`. `dist/*.css` is built from these, not from `index.scss` directly.
- **`dist/`** holds 4 generated files (regular/layer × normal/min). Never hand-edit — regenerated by `scss:watch`/`scss:layer:watch` + `min:css`/`min:layer:css` (postcss-minify) + the banner script. `.stylelintrc` ignores `dist/` entirely.
- **`scripts/update-version.js`** scans `src/**/*.scss` at runtime (no hardcoded file list) for the `// @version X.Y.Z` comment and rewrites it — any new module file is picked up automatically.
- **`scripts/add-banner.js`** + **`scripts/generate-banner.js`** prepend a Bootstrap-style `/*! ... */` banner to compiled CSS (skipped if a banner already exists).

## Conventions

- Module filenames follow `_<name>.rz.scss`.
- Every module carries a doc header: `@summary` / `@version` / `@access` / `@author` / `@license` / `@repository` — match this when adding a module.
- Stylelint (`.stylelintrc`, extends `stylelint-config-standard(-scss)`): `!important` disallowed, hex colors must be long-form, no named colors, custom properties and keyframe names must match `rz-.+`.
- Browser target (`.browserslistrc`): `> 0.5%, last 2 versions, not dead`. The reset relies on CSS `@layer`, `:where()`, and logical properties — no IE support (the 2.x release line is the legacy fallback for older browsers).

## Pull requests

When creating a PR (`gh pr create`), use `.github/Pull_request_template.md` as the `--body` — fill in its sections (`Issue | Task Number`, `What does this pull request do?`, `What is the relevant issue link`, `Screenshot`, `Any additional information?`) instead of the default Summary/Test plan format.

## Issues

When creating an issue (`gh issue create`), pick the matching template from `.github/ISSUE_TEMPLATE/` and fill in its sections as the `--body`:

- **`bug.md`** — bug reports: Describe the bug, To Reproduce, Expected behavior, Screenshots, Desktop/Smartphone info, Additional context. Title prefix `[BUG] - `, label `bug`.
- **`feature.md`** — feature requests: problem description, Describe the solution you'd like, Describe alternatives you've considered, Additional context. Title prefix `[FEAT] - `, label `feature`.
- **`docs.md`** — documentation/workflow changes: What will you like to add or remove?, Typo fix?, Workflow. Title prefix `[DOCS] - `, label `documentation`.
